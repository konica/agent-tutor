Data flow · Smart Tutor evals

Run evaluators against a dataset

How to

  1. For ask, the target is the agent's ask graph built inside the eval process, with real Bedrock models and the stack's MCP server; the question-screen and topic-check targets call only their own check.
  2. Code evaluator: add a function in backend/evals/evaluators/ that returns a score for one item.
  3. LLM judge: write the rubric in evaluators/rubrics/<name>.md; the judge is the Qwen judge role at temperature 0.
  4. Add it to the suite (suite.py: a dataset, a target, its evaluators) and give the metric a min, max or max_failures in thresholds.yaml → release_1.
  5. Run make evals-smoke locally; CI runs the same on PRs that change the agent (evals-smoke.yml) and posts the PASS/FAIL table to the job summary.
  6. A metric no suite scored is never a pass, and an evaluator that crashes counts as a failure.

Status

Today the suite reads its datasets from LangSmith (newest smoke-v2, full-v1) and its results show there. Issue #320 switches the run to the Langfuse dataset versions and records it as a Langfuse experiment in smart-tutor-evals (Datasets → the version → Runs), where runs can be compared side by side.
