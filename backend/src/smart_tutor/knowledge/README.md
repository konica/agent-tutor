# `knowledge` module (Release 1)

**Owns** (PRD §9.2 document processing, §9.3, §9.4, §9.5, US-2, US-2b, US-10, US-11): The learner's library: contents deduplicated by SHA-256 (state machine, shared retry), documents (library entries with 1–3 subjects, state, archive flag, visibility, grants), the single `can_read` access rule, upload, ingestion (first-pages step, page text with `pypdf` and saved output, work key), chunks, and search.

**Key classes:** `Content` (states, `retry()`), `Document` (states, `set_subjects()` 1–3, `archive()`, `restore()`, `can_be_read_by()`, `searchable_by()`), `ChunkHit` (a search result: chunk id, document, display title, page or `None`, text, cosine score), `Chunk`, `FileLimits` (`max_bytes`, `max_pages`; loaded once at startup by `load_file_limits` from the SSM parameters `max-upload-mb` and `max-pages` through the shared `ParameterStore` port); services `UploadService`, `DeduplicationService`, `IngestionService`, `DocumentService`, `SearchService`; adapters `PypdfExtractor` (implements `PdfExtractor`), chunkers from the registry `knowledge.adapters.chunking.build_chunker` (settings `chunking`); ports `PdfExtractor` (`extract_pages(data, max_pages)` raises `TooManyPagesError`), `FirstPagesReader`, `ObjectStore`, `ContentRepository`, `DocumentRepository`, `ChunkRepository`.

**May use (application layer only):** `subjects` (suggestions, get-or-create subjects, names), `accounts` (rate limits, document-processing usage). Everyone may use `shared`.

**Rules:** The PDF loader is imported only in `knowledge.adapters` (ADR 0005). Existing content is linked only after a server-computed SHA-256 of uploaded bytes, never on a browser hash (PRD D19). Every read goes through `can_read`. Documents store `subject_id`s only. Search returns chunks only from ready, non-archived documents. `SearchService.search(user_id, query, subject_ids, k=5)` rejects a blank query, a query over 4000 characters, not 1–3 subjects, a subject id that is not a UUID, or `k` outside 1–20 with `InvalidSearchError`; it embeds the query outside the transaction, then runs an exact (no HNSW) nearest-first search whose SQL filter (`readable_by`, ready, not archived, any requested subject) has `Document.searchable_by` as its domain twin. `DocumentService.learner_subjects` returns "My subjects": the subjects of the learner's ready, non-archived documents. Upload keys are `uploads/<user_id>/<upload_id>.pdf`; the worker hashes the bytes and stores new contents at `contents/<sha256>.pdf`. `IngestionService.process_content` runs after the store commit and re-runs on redelivery while the content is `processing`; it holds no DB transaction during extraction or embedding. It extracts page text, saves it at `contents/<sha256>.pages.json` (`text_key`), chunks, embeds, and writes chunks via `ChunkRepository`, then makes the content `ready`. A PDF over the page limit fails before its text is read with "This PDF has N pages; the limit is 500"; a non-PDF fails with "This file isn't a readable PDF"; a PDF without text with "No text layer (scanned PDFs are not supported yet)"; none leaves chunks. Interim until US-2b: a document whose content becomes `ready` gets `GENERAL_SUBJECT_ID` and goes straight to `ready`. Until US-11, a known hash fails the document with "Duplicate uploads aren't supported yet".

Layout: `domain/` → `ports/` ← `application/`, `adapters/`. Other modules import only `knowledge.application`.
