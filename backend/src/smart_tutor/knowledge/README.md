# `knowledge` module (Release 1)

**Owns** (PRD §9.2 document processing, §9.3, §9.4, §9.5, US-2, US-2b, US-10, US-11): The learner's library: contents deduplicated by SHA-256 (state machine, shared retry), documents (library entries with 1–3 subjects, state, archive flag, visibility, grants), the single `can_read` access rule, upload, ingestion (first-pages step, page text with `pypdf` and saved output, work key), chunks, and search.

**Key classes:** `Content` (states, `retry(max_attempts)`), `Document` (states, `retry()`, `set_subjects()` 1–3, `archive()`, `restore()`, `can_be_read_by()`, `searchable_by()`), `ChunkHit` (a search result: chunk id, document, display title, page or `None`, text, cosine score), `Chunk`, `FileLimits` (`max_bytes`, `max_pages`; loaded once at startup by `load_file_limits` from the SSM parameters `max-upload-mb` and `max-pages` through the shared `ParameterStore` port), `DocumentDescriber` (one `describe_document` call), `DocumentDescription` (`parse_description`, `work_key`); services `UploadService`, `DeduplicationService`, `IngestionService`, `DocumentService` (`list_documents`, `find_in_library`, `learner_subjects`, `has_ready_documents`), `RetryService`, `SubjectChoiceService` (`suggestions`, `choose`), `SearchService`; adapters `PypdfExtractor` (implements `PdfExtractor`), chunkers from the registry `knowledge.adapters.chunking.build_chunker` (settings `chunking`); ports `PdfExtractor` (`extract_pages(data, max_pages, first=2)` raises `TooManyPagesError`), `ObjectStore`, `ContentRepository`, `DocumentRepository`, `ChunkRepository`.

**May use (application layer only):** `subjects` (suggestions, get-or-create subjects, names), `accounts` (rate limits, document-processing usage). Everyone may use `shared`.

**Rules:** Retry (`RetryService`) gives a failed content another attempt from `contents/<sha256>.pdf`, at most `max-processing-attempts` (SSM, 3) in all, and returns every failed document linked to it to `processing`. It reads the document, then locks the content, then the content's failed documents (the worker's order), and sends `{"retry_content_id": …}` to the ingest queue before committing, under the content's row lock; `process_content` locks the content on its first read, so it waits for that commit. After the last attempt the Library shows "This file could not be processed". The PDF loader is imported only in `knowledge.adapters` (ADR 0005). Existing content is linked only after a server-computed SHA-256 of uploaded bytes, never on a browser hash (PRD D19). The browser duplicate check (`DocumentService.find_in_library`) looks only at the caller's linked, non-archived documents and links nothing. Every read goes through `can_read`. Documents store `subject_id`s only. Search returns chunks only from ready, non-archived documents. `SearchService.search(user_id, query, k=5)` rejects a blank query, a query over 4000 characters, or `k` outside 1–20 with `InvalidSearchError`; it embeds the query outside the transaction, then runs an exact (no HNSW) nearest-first search over all of the learner's documents, whose SQL filter (`readable_by`, ready, not archived) has `Document.searchable_by(user_id)` as its domain twin; each hit carries the document's display title, never its subjects (a conversation has none). `DocumentService.list_documents` narrows the Library by any of several subjects, any of several states, and an inclusive upload date range in the app time zone (GMT+7, PRD D27); the filter is a `DocumentFilter` applied in SQL by `list_readable_by`, with `Document.matches` as its domain twin, and each view carries its content's authors and year. `DocumentService.learner_subjects` returns "My subjects": the subjects of the learner's ready, non-archived documents. `DocumentService.has_ready_documents` says whether the learner has any ready, non-archived document (a thread needs one). Upload keys are `uploads/<user_id>/<upload_id>.pdf`; the worker hashes the bytes and stores new contents at `contents/<sha256>.pdf`. `IngestionService.process_content` runs after the store commit and re-runs on redelivery while the content is `processing`; it holds no DB transaction during extraction or embedding. It first describes pages 1–2 with one `describe_document` call (page text as quoted data), validates the payload in code (an invalid DOI or year is dropped without losing the rest; a DOI not printed in the pages is dropped too), and commits title, authors, year, DOI, summary, summary embedding, proposed subject names, and work key (DOI, else normalized title + year) at once, so the Library shows the title while processing. A reply without one valid call stores none of them and processing continues (the title stays the file name); a described content isn't described again on redelivery. It extracts page text, saves it at `contents/<sha256>.pages.json` (`text_key`), chunks, embeds, and writes chunks via `ChunkRepository`, then makes the content `ready`. A PDF over the page limit fails before its text is read with "This PDF has N pages; the limit is 500"; a non-PDF fails with "This file isn't a readable PDF"; a PDF without text with "No text layer (scanned PDFs are not supported yet)"; none leaves chunks. When its content becomes `ready`, a processing document goes to `awaiting_subjects`; `SubjectChoiceService` serves its suggestions (from `subjects.application.SubjectSuggester`, with the learner's subjects = their ready, non-archived documents' subjects) and saves 1–3 chosen subjects (existing ids, or proposed names through `SubjectCatalogService.get_or_create`), which makes it `ready` and searchable. Until US-11, a known hash fails the document with "Duplicate uploads aren't supported yet".

Layout: `domain/` → `ports/` ← `application/`, `adapters/`. Other modules import only `knowledge.application`.
