# `knowledge` module (Release 1)

**Owns** (PRD §9.2 document processing, §9.3, §9.4, §9.5, US-2, US-2b, US-10, US-11): The learner's library: per-learner contents, unique `(owner_id, sha256)` and never linked to another learner's copy (state machine, retry by the owner), documents (library entries with 1–3 subjects, state, archive flag, visibility, grants), the single `can_read` access rule, upload, ingestion (first-pages step, page text with `pypdf` and saved output, work key), chunks, and search.

**Key classes:** `Content` (states, `retry(max_attempts)`), `Document` (states, `retry()`, `set_subjects()` 1–3, `set_title()`, `archive()`, `restore()`, `can_be_read_by()`, `searchable_by()`), `ChunkPassage` (a cited chunk with its document, page, `start_index`, and text), `ChunkHit` (a search result: chunk id, document, display title, page or `None`, text, cosine score), `Chunk`, `FileLimits` (`max_bytes`, `max_pages`; loaded once at startup by `load_file_limits` from the SSM parameters `max-upload-mb` and `max-pages` through the shared `ParameterStore` port), `DocumentDescriber` (one `describe_document` call), `DocumentDescription` (`parse_description`, `work_key`); services `UploadService` (`upload_status` answers `GET /uploads/{upload_id}` for the caller's own upload only, as an `UploadStatus`; `start_upload` refuses with `accounts`' `UploadLimitReachedError` at the learner's hourly or daily limit; `upload_block` answers `GET /uploads/rate-limit` for the caller only), `IngestionService`, `ArchiveService` (`archive`, `restore`), `DeleteService` (`delete`), `DocumentService` (`details`, `set_title`, `list_documents`, `find_in_library`, `learner_subjects`, `documents_by_id`), `RetryService`, `SubjectChoiceService` (`suggestions`, `choose`), `ViewerService` (`file`, `passage`), `SearchService`, `StartIndexBackfill` (`run`, at worker startup); adapters `PypdfExtractor` (implements `PdfExtractor`), chunkers from the registry `knowledge.adapters.chunking.build_chunker` (settings `chunking`); ports `PdfExtractor` (`extract_pages(data, max_pages, first=2)` raises `TooManyPagesError`), `ObjectStore` (`presign_post`, `presign_get`, `read`, `put`, `copy`, `delete`, `delete_all_versions`), `ContentRepository`, `DocumentRepository`, `ChunkRepository` (`replace`, `remove_for_content`, `contents_missing_start_index`, `list_for_content`, `set_start_indexes`, `get_readable`, `search`).

**May use (application layer only):** `subjects` (suggestions, get-or-create subjects, names), `accounts` (rate limits, document-processing usage). Everyone may use `shared`.

**Rules:** `start_upload` takes a per-learner advisory lock (`UploadRepository.lock_learner`), counts the learner's `uploads` rows since `UploadLimits.since` (every started upload counts: duplicates, failed, and never-sent ones; deleting a document keeps its upload row), and presigns only when `UploadLimits.check` allows it. Retry (`RetryService`) gives a failed content another attempt from `contents/<owner_id>/<content_id>.pdf`, at most `max-processing-attempts` (SSM, 3) in all, and returns every failed document linked to it to `processing`. It reads the document, then locks the content, then the content's failed documents (the worker's order), and sends `{"retry_content_id": …}` to the ingest queue before committing, under the content's row lock; `process_content` locks the content on its first read, so it waits for that commit. After the last attempt the Library shows "This file could not be processed". The PDF loader is imported only in `knowledge.adapters` (ADR 0005). A duplicate is decided only by the server-computed SHA-256 of uploaded bytes within the learner's own contents, never on a browser hash (PRD D19): the worker's insert-or-get uses `(owner_id, sha256)`; a hash matching one of the learner's own contents deletes the upload copy, records outcome `duplicate`, removes the placeholder document, and points the upload (`uploads.document_id`) to the existing document. The browser duplicate check (`DocumentService.find_in_library`) looks only at the caller's linked, non-archived documents and links nothing. Every read goes through `can_read`; its lookups (`get_readable`, `list_readable_by`, `get_readable_by_sha256`) return archived documents too, and `DocumentFilter.archived` (True, False, or None) selects, so callers that need active documents (`learner_subjects`, `find_in_library`, subject choice) filter explicitly. `ArchiveService` archives and restores through `Document.archive(at)` and `Document.restore()`: they set and clear only `archived` and `archived_at` (any state; repeating either is harmless, a second archive keeps the first `archived_at`), and content, chunks, subjects, and state stay as they are; an archived document that finishes processing stays archived. `DeleteService.delete` refuses only a `processing` document (`Document.check_deletable`, API 409); it reads the document, locks its content, then the document (the retry's order) and checks again, calls `keep_title` (tutoring copies the display title into the learner's `thread_documents` in its own transaction, so a failed delete leaves only a harmless copy), removes the document with its subjects, the content's chunks and the content, commits, then deletes every S3 version of `contents/<owner_id>/<content_id>.pdf` and `.pages.json`; a storage failure after the commit is logged. Choosing the subjects of an archived document raises `DocumentStateError` (API 409) until it is restored. Documents store `subject_id`s only. Search returns chunks only from ready, non-archived documents. `SearchService.search(user_id, query, k=5, document_ids=None)` rejects a blank query, a query over 4000 characters, or `k` outside 1–20 with `InvalidSearchError`; it embeds the query outside the transaction, then runs an exact (no HNSW) nearest-first search over all of the learner's documents (or only those in `document_ids`, a conversation limited to its documents, US-4c: malformed ids are dropped, more than 200 is `InvalidSearchError`, ids the caller can't read match nothing), whose SQL filter (`readable_by`, ready, not archived) has `Document.searchable_by(user_id)` as its domain twin; each hit carries the document's display title, never its subjects (a conversation has none). `DocumentService.list_documents(..., archived=False)` lists active documents, or archived ones with `archived=True`, and narrows the Library by any of several subjects, any of several states, and an inclusive upload date range in the app time zone (GMT+7, PRD D27); the filter is a `DocumentFilter` applied in SQL by `list_readable_by`, with `Document.matches` as its domain twin, and each view carries its content's authors and year. `DocumentService.learner_subjects` returns "My subjects": the subjects of the learner's ready, non-archived documents. `DocumentService.documents_by_id(user_id, ids)` returns the learner's documents among the ids as views, archived included (a conversation's documents used list them, US-4b); others' and unknown ids are absent. `ViewerService.file` reads through `can_read` (archived included), serves only `ready` and `awaiting_subjects` documents (409 otherwise), and presigns a 300-second GET for `contents/<owner_id>/<content_id>.pdf`; the viewer renews it. `ViewerService.passage` reads a chunk through `can_read` in SQL (`ChunkRepository.get_readable`; archived included, any state); others' and unknown chunks are `ChunkNotFoundError` (API 404). `DocumentService.details` returns one of the learner's documents (archived or not, through `get_readable`) with its own content's authors, year, DOI, pages, summary, and extracted title. `DocumentService.set_title` sets `documents.title_override` through `Document.set_title` (cleaned with `clean_title`: one line, control and bidi characters removed, 1–300 characters, else `InvalidTitleError`); None, or the extracted title itself, clears it. It never changes `contents.title`; search and the documents used read the display title at read time. Upload keys are `uploads/<user_id>/<upload_id>.pdf`; the worker hashes the bytes and stores new contents at `contents/<owner_id>/<content_id>.pdf`, the content id derived from the upload id (UUIDv5) so a redelivery reuses the key. `IngestionService.process_content` runs after the store commit and re-runs on redelivery while the content is `processing`; it holds no DB transaction during extraction or embedding. It first describes pages 1–2 with one `describe_document` call (page text as quoted data), validates the payload in code (an invalid DOI or year is dropped without losing the rest; a DOI not printed in the pages is dropped too), and commits title, authors, year, DOI, summary, summary embedding, proposed subject names, and work key (DOI, else normalized title + year) at once, so the Library shows the title while processing. A reply without one valid call stores none of them and processing continues (the title stays the file name); a described content isn't described again on redelivery. It extracts page text, saves it at `contents/<owner_id>/<content_id>.pages.json` (`text_key`), chunks, embeds, and writes chunks via `ChunkRepository`, each with its `start_index` (offset in its page's cleaned text, `clean_page_text`), or null when the splitter couldn't place it, then makes the content `ready`. `StartIndexBackfill.run` (worker startup) gives chunks without `start_index` their offset by locating their text (`locate_chunks`) in their page's cleaned saved text; chunk ids never change; a chunk it can't locate, or one whose `.pages.json` is missing, stays null and is logged. A PDF over the page limit fails before its text is read with "This PDF has N pages; the limit is 500"; a non-PDF fails with "This file isn't a readable PDF"; a PDF without text with "No text layer (scanned PDFs are not supported yet)"; none leaves chunks. When its content becomes `ready`, a processing document goes to `awaiting_subjects`; `SubjectChoiceService` serves its suggestions (from `subjects.application.SubjectSuggester`, with the learner's subjects = their ready, non-archived documents' subjects) and saves 1–3 chosen subjects (existing ids, or proposed names through `SubjectCatalogService.get_or_create`), which makes it `ready` and searchable.

Layout: `domain/` → `ports/` ← `application/`, `adapters/`. Other modules import only `knowledge.application`.
