# `tutoring` module (Release 1)

**Owns** (PRD §9.2, US-3, US-4 to US-6, US-13): Threads (no subjects; they keep their documents used (US-4b)), relevance gate, the ask path, conversation management.

**Key classes:** `Thread`, `Turn`, `Rating`, `RelevanceGate`; services `AskService`, `ConversationService`; ports `Retriever`, `ThreadRepository`, `AnswerFeedback`, `Guard` (adapters `GuardrailsGuard`, `BedrockQuestionScreen`: a Bedrock ApplyGuardrail question screen that fails open, counted; `GuardTrip`).

**Built so far:** `Thread` and `ThreadRepository` (`SqlThreadRepository`); `ConversationService.start_thread(user_id, question)` (the title starts as the first question; a learner with no ready, non-archived document gets a thread too, whose turn is the agent's `no_documents` decline, `NO_DOCUMENTS_DECLINE`); `update_thread` (`Thread.rename`: trimmed, 1–120 characters, refused while archived; also `search_scope`, `library` or `listed`, which limits the search to the conversation's documents (US-4c); `search_documents` reads the ids; removing the last listed document turns the limit off); `Retriever` with its MCP client adapter `McpRetriever` (`search(query, k, document_ids=None)` over all of the learner's ready documents, or only the given ones); `covers` and `LIMITED_DECLINE` (a limited search with no chunk at or above `answer_floor` is declined, US-4c); `answer_messages` / `cited_chunks` (the quoted answer prompt, after the capped history as earlier messages, and its citations); `search_query` (a follow-up adds the previous question, in code); documents used: `ConversationService.record_turn` (adds a kept turn's documents in order of first use, no duplicates) and `documents_used` (resolved now: title, authors, year, archived, or "Deleted document"), stored as `ThreadDocument` rows. The learner's additions and removals (`add_documents`, only their ready, non-archived documents; `remove_document`); rows record `added_by`. `ConversationService.keep_deleted_title(user_id, document_id, title)` copies a document's title onto its rows in that learner's threads just before the document is deleted. Conversation history: `ConversationService.record_turn` keeps a turn whose answer ended with `done` (question, answer, citations as ids and page, or the decline) with its documents used in one transaction, as `Turn` rows (`thread_turns`); `turns` reads them oldest first through owner-scoped SQL and resolves citations now (title, archived, or "Deleted document"). `ConversationService.list_threads` returns the owner's active threads, newest last activity first, optionally filtered by subject, last-activity days, and title (`GET /threads` query `subject_id`, `active_from`, `active_to`, `q`), as `ThreadSummary` (subject ids of listed documents that still exist, and the number listed); `note_question` updates `last_learner_message_at` when a question is asked in an existing thread. `ConversationService.history` reads the last `history_turns` turns (default 5, oldest first; owner-scoped SQL, `last_turns`) as `HistoryTurn` (question and answer text or decline message, answers cut to `history_answer_chars`), which the API sends with a question in an existing thread (ADR 0015). Ratings (PRD §10.2, #227): `ConversationService.rate_turn(thread_id, user_id, run_id, rating)` saves the owner's `Rating` (`up` or `down`; a new one replaces it) on the turn of that run (`thread_turns.rating`, `Turn.rating`; `TurnNotFoundError` if there is no such turn), then sends it through the `AnswerFeedback` port; a failed send is logged and never fails the rating. The API wires `PhoenixAnswerFeedback` (`answer_feedback(settings)`, #290), which sends the rating to Phoenix as a `learner_rating` annotation on the turn's root span (`NoAnswerFeedback` when tracing is off). Output guard (PRD §9.2 step 4, D28, D29, ADR 0018, #197): the `Guard` port has a question check and an answer check; `GuardrailsGuard` runs a Guardrails AI `AsyncGuard` in process with our `SystemPromptLeak` validator (a random per-process canary, or a 40-character run of the system prompt). The agent checks the accumulated answer before each streamed piece leaves; a trip ends the stream with a `replace` event and the guard message, and the API keeps the turn as `Decline("guard", message)` with no documents used. `last_turns` and `history` leave out `guard` turns (the history limit counts only other turns). An output guard that raises fails closed with the `unavailable` error and the turn is not kept. The question check is `BedrockQuestionScreen` (D30, ADR 0019), which wraps the output guard and sends only the question to Bedrock ApplyGuardrail; the agent's `screen` node runs it before search when `question_guard` is `bedrock` (default `off`). A trip ends the turn as above with reason `guard_question`, and search and the model are not called. Unlike the output guard it fails open: on an error or timeout the question goes on unscreened and the failure is counted (`QuestionScreenFailures`). `AskService`, `RelevanceGate`, and conversation management are still to come.

**May use (application layer only):** `knowledge` (`DocumentService.documents_by_id`, to resolve the documents used and citations; `DocumentService.documents_with_subjects`, to filter conversations by subject; `DEFAULT_TIME_ZONE`), `subjects`, `accounts`, `insights` (log declines). Everyone may use `shared`.

**Rules:** Never reads chunk tables: retrieval goes through the `Retriever` port (MCP client adapter). A thread has no subjects and answers from all of the learner's ready documents. Document text and the learner's question are passed to the model as quoted data. Guardrails AI is imported only in `adapters` (the agent image's `guard` extra). Never imports `learning`.

Layout: `domain/` → `ports/` ← `application/`, `adapters/`. Other modules import only `tutoring.application`.
