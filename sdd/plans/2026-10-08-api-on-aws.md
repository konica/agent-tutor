# A learner signs in to Smart Tutor on AWS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The API runs on EKS behind CloudFront at `/api`, migrations run as a Helm hook before it rolls out, and a learner signs in at the CloudFront address, lands on the Library with their name, and signs out; the API answers 401 to every call without a valid token.

**Architecture:** The ALB forwards `/api/me` unchanged, and the API's routes have no prefix (`/me`), so the API sets FastAPI's `root_path` from a new setting `SMART_TUTOR_ROOT_PATH=/api`: FastAPI then serves both `/api/me` (through CloudFront) and `/me` (probes, in-cluster). `EdgeStack` adds an API target group, an ALB rule for `/api/*`, and an uncached CloudFront behavior for `/api/*`, the same shape as `/auth/*` (#57). `ClusterStack` gives the API's service account an IAM role through Pod Identity that may only read the `/smart-tutor/*` SSM parameters, which the API loads at startup. In the cluster, the `api` chart runs the API with the production issuer, the in-cluster Keycloak URL for introspection, and the database URL and client secret from External Secrets; the `jobs` chart runs `python -m smart_tutor.apps.jobs.migrate` as a pre-install/pre-upgrade hook after the existing `db-bootstrap` hook.

**Tech Stack:** FastAPI 0.142 / Starlette 1.7, pydantic-settings, aws-cdk-lib (`aws_cloudfront`, `aws_elasticloadbalancingv2`, `aws_eks`, `aws_iam`), External Secrets `external-secrets.io/v1`, Helm, pytest + PyYAML.

**Spec:** GitHub issue #58 (parent #54); PRD §9.3, §9.11, §9.12; ADR 0007 (token introspection), ADR 0009 (CloudFront domain with path routing), ADR 0010 (Keycloak edge); plans `sdd/plans/2026-10-05-public-web-cloudfront.md` (#56) and `sdd/plans/2026-10-06-keycloak-auth-rds.md` (#57), which this extends.

**Spike (2026-10-08, already done):** `FastAPI(root_path="/api")` on FastAPI 0.142.2 / Starlette 1.7.0 answers 200 on `/api/me`, `/me`, `/healthz` and `/api/healthz`; the OpenAPI document lists `servers: [{"url": "/api"}]`. (Uvicorn's `--root-path` is **not** the same: it prepends the prefix, for proxies that strip it, so `/api/me` would become `/api/api/me`.)

**Already true, no work:** the web image is built with `VITE_API_URL=/api` and calls the API on its own origin (`web/src/api/client.ts`, test `client.test.ts`; #56). A Keycloak outage already gives 401, not 5xx (`IntrospectionUnavailableError` → 401 in `shared/adapters/auth/bearer.py`). The `smart-tutor/api` ECR repository and the `smart-tutor/keycloak/api-client` secret exist (#56, #57); the production realm already holds the `smart-tutor-api` client with that secret.

## Global Constraints

- Names: namespace `smart-tutor`; Deployment, Service, and ServiceAccount `api`; target group `smart-tutor-prod-api` (Edge output `ApiTargetGroupName`); listener rule priority **20** for `/api/*` (Keycloak keeps 10); Kubernetes Secrets `api-db` (key `url`), `api-keycloak` (key `client-secret`), `migrate-db` (key `url`); image `smart-tutor/api` (fix the stale `smart-tutor-api` in `charts/api/values.yaml` and `charts/jobs/values.yaml`).
- The API listens on 8080, like web and Keycloak, so the existing ALB → pod security-group rule (`POD_PORT`) covers it.
- API environment in production: `SMART_TUTOR_ENVIRONMENT=prod`, `SMART_TUTOR_ROOT_PATH=/api`, `SMART_TUTOR_KEYCLOAK_ISSUER=<publicUrl>/auth/realms/smart-tutor`, `SMART_TUTOR_KEYCLOAK_INTERNAL_URL=http://keycloak/auth/realms/smart-tutor`, `SMART_TUTOR_KEYCLOAK_CLIENT_ID=smart-tutor-api`, `SMART_TUTOR_KEYCLOAK_CLIENT_SECRET` from `api-keycloak`, `SMART_TUTOR_DATABASE_URL` from `api-db`, `SMART_TUTOR_CORS_ORIGINS=[]` (same origin, no CORS), `SMART_TUTOR_AWS_REGION=us-east-1`, `HOME=/tmp`.
- Database URL (both `api-db` and `migrate-db`), built by an External Secrets template from `smart-tutor/db/app`: `postgresql+psycopg://{{ .username }}:{{ .password }}@{{ .host }}:{{ .port }}/{{ .dbname }}?sslmode=require`. The generated passwords have no punctuation, so they are URL-safe.
- Hook order: `SecretStore` −20 → `db-bootstrap` ExternalSecret and ConfigMap −10 → `db-bootstrap` Job 0 → `migrate-db` ExternalSecret 5 → `migrate` Job 10. Hook delete policy `before-hook-creation,hook-succeeded` (as `db-bootstrap`). A failed hook Job fails the release, so the API never rolls out on a failed migration.
- The API's IAM role (Pod Identity, `smart-tutor`/`api`) may only call `ssm:GetParameter` and `ssm:GetParameters` on `arn:aws:ssm:<region>:<account>:parameter/smart-tutor/*`. S3, SQS, and Bedrock come with the slice that turns on upload and chat on AWS; until then those calls fail on AWS and only sign-in and the Library are in scope.
- `helm lint deploy/helm/smart-tutor` with default values must keep passing (CI). With `global.secretStore` set and `global.publicUrl` empty, rendering the `api` chart must **fail** (a wrong issuer would reject every token silently).
- No secret value in Git, Helm values, rendered manifests, or CI logs.
- The agent, MCP server, and worker stay `enabled: false` in `values-prod.yaml`.
- Commits: imperative subject, body says why, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Checks: `cd backend && uv run ruff check . && uv run ruff format --check . && uv run mypy && PYTHONUTF8=1 uv run lint-imports && uv run pytest`; `cd infra && JSII_SILENCE_WARNING_UNTESTED_NODE_VERSION=1 uv run pytest -q`; `helm lint deploy/helm/smart-tutor`; `helm lint deploy/helm/smart-tutor -f deploy/helm/smart-tutor/values-prod.yaml --set global.publicUrl=https://d111.cloudfront.net`.

## Review Focus

1. **A production render without `global.publicUrl`.** The API would start with the localhost issuer and reject every token. Pinned in Task 3 (`test_api_refuses_to_render_for_aws_without_public_url`).
2. **Requests through CloudFront keep their prefix.** `/api/me` must reach the `/me` route, and the ALB health check must pass. Pinned in Task 1 (`test_routes_answer_under_the_root_path`) and Task 2 (`test_api_target_group_takes_api_paths_on_8080`).
3. **`Authorization` reaching the API through CloudFront, for every method.** Pinned in Task 2 (`test_cloudfront_sends_api_uncached_with_every_method`).
4. **The migration running before the API, after the databases exist, on every upgrade.** Pinned in Task 3 (`test_migrate_runs_as_a_hook_after_db_bootstrap`).
5. **Secrets leaking into manifests.** The existing `test_rendered_manifests_hold_no_secret_values` covers the new charts once `api` and `jobs` render in prod values; Task 3 extends its prod render to them.
